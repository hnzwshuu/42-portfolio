# get_next_line

## Description

`get_next_line` は、ファイルディスクリプタから 1 行ずつ読み取る C 関数を
実装する 42 カリキュラムのプロジェクトです。

このプロジェクトの目的は、`read`、動的メモリ確保、静的変数、そして慎重な
バッファ管理を使い、C における低レベル入力の仕組みを理解することです。
この関数は呼び出されるたびに次の 1 行を返し、改行文字が存在する場合は
その改行文字も含めます。読み取るデータが残っていない場合、またはエラーが
発生した場合は `NULL` を返します。

主なファイル:

- `get_next_line.c`: 行読み取りの中心となる処理
- `get_next_line_utils.c`: 文字列操作やメモリ確保を行う補助関数
- `get_next_line.h`: 関数プロトタイプ、インクルード、`BUFFER_SIZE` の定義
- `main.c`: ローカル用のテストプログラム

## Instructions

```sh
cc -Wall -Wextra -Werror get_next_line.c get_next_line_utils.c main.c
```

コンパイル時に任意のバッファサイズを指定するには:

```sh
cc -Wall -Wextra -Werror -D BUFFER_SIZE=42 get_next_line.c get_next_line_utils.c main.c
```

テストプログラムを実行するには:

```sh
./a.out
```

## Algorithm Explanation and Justification

このアルゴリズムでは、関数呼び出しの間で未読データを保持するために
`stash` という静的変数を使います。

`get_next_line` は呼び出されるたびに、次の手順で動作します。

1. ファイルディスクリプタと `BUFFER_SIZE` が有効か確認します。
2. `stash` がまだ存在しない場合は、空文字列として初期化します。
3. ファイルディスクリプタから `BUFFER_SIZE` の大きさの一時バッファに読み込みます。
4. 改行が見つかるか、`read` がファイル終端に到達するまで、読み込んだ
   バッファを `stash` に追加します。
5. `stash` の先頭から、改行がある場合はその改行までを含めてコピーし、
   返す 1 行を作成します。
6. 返した行の後ろに残っている未読文字だけを保持するように `stash` を更新します。
7. 返すデータがもうない場合、またはメモリ確保や読み込みでエラーが起きた場合は、
   メモリを解放して `NULL` を返します。

この方法を選んだ理由は、`read` は論理的なテキストの 1 行がどこで終わるかを
知らないためです。1 回の `read` 呼び出しで、1 行未満、ちょうど 1 行、または
1 行を超えるデータが返ることがあります。静的変数 `stash` は、すでに読み込まれた
ものの後の呼び出しで返すべき余分なバイトを保持することで、この問題を解決します。

この実装では、ファイル全体を一度に読み込むことも避けています。次の 1 行を
作るために必要な分だけ読み込むため、大きなファイルやストリームにも対応できます。
メモリの所有関係も明確にしています。一時バッファは結合後に解放し、古い `stash` は
置き換えるときに解放し、返された各行を解放する責任は呼び出し元にあります。
